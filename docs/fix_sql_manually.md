# Manual Fix for Password Hash Column Length

This guide provides step-by-step instructions to manually fix the password hash column length issue in the Cloud SQL database.

## Problem Description

The error in the logs shows:
```
ERROR in auth: Error registering user: (pg8000.dbapi.ProgrammingError) {'S': 'ERROR', 'V': 'ERROR', 'C': '22001', 'M': 'value too long for type character varying(128)', 'F': 'varchar.c', 'L': '635', 'R': 'varchar'}
```

This is because the password hash being generated by the current hashing algorithm (scrypt) is longer than the 128 character limit defined in the database schema.

## Solution: Alter the Database Column

1. **Connect to Cloud SQL**

   First, establish a connection to your PostgreSQL database in Cloud SQL. You can use one of these methods:

   ### Option 1: Cloud SQL Auth Proxy (Recommended)
   ```bash
   # Download Cloud SQL Auth Proxy if needed
   curl -o cloud-sql-proxy https://storage.googleapis.com/cloud-sql-connectors/cloud-sql-proxy/v2.6.1/cloud-sql-proxy.darwin.amd64
   chmod +x cloud-sql-proxy

   # Start the proxy
   ./cloud-sql-proxy find-a-meeting-spot:us-east1:findameetingspot --port=5433

   # In a separate terminal, connect to the database
   psql -h localhost -p 5433 -U meetingspot -d findameetingspot
   # Enter password when prompted: MeetingSpot123!
   ```

   ### Option 2: Cloud Shell in Google Cloud Console
   ```bash
   # Open Cloud Shell and connect to your database
   gcloud sql connect findameetingspot --user=meetingspot
   # Enter password when prompted: MeetingSpot123!
   ```

2. **Execute the ALTER TABLE Command**

   Once connected to the database, run this SQL command:

   ```sql
   -- Check current column definition
   SELECT column_name, data_type, character_maximum_length
   FROM information_schema.columns
   WHERE table_name = 'users' AND column_name = 'password_hash';

   -- Alter the column to 256 characters
   ALTER TABLE users
   ALTER COLUMN password_hash TYPE varchar(256);

   -- Verify the change
   SELECT column_name, data_type, character_maximum_length
   FROM information_schema.columns
   WHERE table_name = 'users' AND column_name = 'password_hash';
   ```

3. **Update Application Code**

   After modifying the database, update the User model in your code to match:

   ```python
   # In app/models/user.py, change:
   password_hash = db.Column(db.String(128), nullable=True)  # Allow null for OAuth users

   # To:
   password_hash = db.Column(db.String(256), nullable=True)  # Allow null for OAuth users
   ```

4. **Redeploy the Application**

   ```bash
   # Redeploy your application
   ./deploy_to_cloud_run.sh
   ```

## Verify the Fix

1. Try registering a new user through the website.
2. Check the logs to confirm no more errors about password_hash length.

## Additional Notes

If you continue having issues, consider:

1. Reviewing the scrypt configuration in your application to generate shorter hashes
2. Ensuring your migrations are properly applied in the production environment
3. Checking for any caching issues in your application or the database
